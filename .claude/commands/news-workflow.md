# 뉴스 수집기 기능 개발 워크플로우

뉴스 수집기 앱에서 새 기능을 개발할 때 쓰는 명령입니다.
브랜치 이름: $ARGUMENTS

모든 응답은 한글로 작성합니다. (코드, 명령어, 파일명 등은 원문 그대로)

## 1단계: 현재 상태 확인

1. `git branch --show-current`와 `git status`로 현재 브랜치와 작업 트리 상태를 확인한다.
2. 현재 브랜치가 `main`이 아니면:
   - 경고를 보여준다. (예: "현재 `xxx` 브랜치입니다. 새 기능 브랜치는 main에서 시작해야 합니다.")
   - main으로 이동할지 사용자에게 묻고, 사용자가 동의하면 `git checkout main`으로 이동한다.
   - 커밋되지 않은 변경사항이 있어 이동이 안 되면 그 사실을 알리고 처리 방법을 묻는다.
   - 사용자가 거절하면 여기서 중단한다.

## 2단계: 브랜치 생성

1. `$ARGUMENTS`가 비어 있지 않으면 그 이름으로 `git checkout -b <이름>`을 실행한다.
2. `$ARGUMENTS`가 비어 있으면:
   - 어떤 기능을 개발할 것인지 사용자에게 묻는다.
   - 답변을 바탕으로 **영어 소문자-하이픈** 형식의 브랜치 이름을 제안한다. (예: `category-crud`, `notion-save`)
   - 사용자가 확인하면 그 이름으로 브랜치를 만든다.

## 3단계: 개발 시작 안내

브랜치 생성이 끝나면 "이제 개발을 시작하세요!"라고 안내하고, 프로젝트 `CLAUDE.md`를 읽어 아래 내용을 다시 한번 알려준다.

- 기술 스택: Next.js(App Router) / React / TypeScript / Tailwind v4, Clerk 인증, Neon + Drizzle ORM, Claude API, Notion 저장
- 컨벤션: 임포트 별칭 `@/*` → `src/*`, 모든 UI 문구와 요약은 한국어, API 키는 환경변수로만 관리
- 주의사항: 코드 작성 전 `node_modules/next/dist/docs/`의 관련 가이드 확인, UI 작업 전 `ui.md` 확인, 요구사항 기준은 `PRD.md`

## 4단계: 완료 처리

사용자가 **'완료'** 또는 **'done'**이라고 입력하면:

1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여준다.
2. 변경 내용을 바탕으로 커밋 메시지를 제안한다. 최근 커밋 로그(`git log --oneline -5`)의 스타일(한국어, `주제: 설명` 형식)을 따르고, 시스템에서 지정한 Co-Authored-By 줄을 끝에 붙인다.
3. 사용자가 확인하면 변경 파일을 add하고 커밋한다. 수정 요청이 있으면 메시지를 고쳐서 다시 확인받는다.
4. 커밋 후 `git checkout main`으로 이동해 기능 브랜치를 병합(`git merge <브랜치>`)한다.
5. 병합 중 충돌이 나면 임의로 해결하지 말고 충돌 파일을 알리고 사용자에게 처리 방법을 묻는다.

## 5단계: 작업 요약

병합이 끝나면 아래를 요약해서 보여준다.

- 브랜치 이름과 병합 결과
- 커밋 메시지
- 변경된 파일 목록과 각 파일에서 한 일
- 구현한 기능의 핵심 내용

병합된 기능 브랜치를 삭제할지는 사용자에게 묻고, 동의할 때만 삭제한다.
